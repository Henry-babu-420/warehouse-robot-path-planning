## 2. Standard 2D $A^*$ Path Planning Complexity

### 2.1 Graph Formulation
Let the warehouse floor be modeled as an undirected planar graph $G = (V, E)$:
- **Vertices $V$:** The set of 2D grid coordinates $(x, y) \in [0, W-1] \times [0, H-1]$ where cell $(x, y)$ is traversable (non-shelf, non-wall, non-obstacle).
  $$|V| \le W \times H$$
  For the standard $20 \times 14$ warehouse grid, $|V|_{max} = 280$. With shelves and perimeter walls, $|V|_{traversable} \approx 192$.
- **Edges $E$:** 4-connected transitions between cardinal neighbors (North, South, East, West).
  $$|E| \le 4 |V|$$

### 2.2 Heuristic Function Properties
The heuristic function $h(u, v)$ estimates the remaining distance from state $u = (x_1, y_1)$ to goal $v = (x_2, y_2)$ using the Manhattan distance:
$$h(u, v) = |x_1 - x_2| + |y_1 - y_2|$$

#### 2.2.1 Admissibility Proof
Let $d^*(u, v)$ denote the true shortest path distance between $u$ and $v$ on graph $G$. Since every edge transition has a unit cost $c(u, w) = 1$, any physical traversal in a 4-connected grid requires at least $|x_1 - x_2|$ horizontal steps and $|y_1 - y_2|$ vertical steps, even in the complete absence of obstacles.
$$\therefore h(u, v) \le d^*(u, v), \quad \forall u, v \in V$$
Because $h(u, v)$ never overestimates the true cost to reach the goal, $A^*$ is admissible and guarantees an optimal path.

#### 2.2.2 Monotonicity (Consistency) Proof
A heuristic is consistent if for every node $u$ and every successor $w$ generated by action $a$:
$$h(u, v) \le c(u, w) + h(w, v)$$
For any adjacent node $w$ in a 4-connected grid, $|x_u - x_w| + |y_u - y_w| = 1 = c(u, w)$. By the triangle inequality of absolute values:
$$|x_u - x_v| \le |x_u - x_w| + |x_w - x_v|$$
$$|y_u - y_v| \le |y_u - y_w| + |y_w - y_v|$$
Summing both inequalities:
$$h(u, v) \le 1 + h(w, v) = c(u, w) + h(w, v)$$
Because $h(u, v)$ is monotone, the sequence of $f(n) = g(n) + h(n)$ values along any optimal path is non-decreasing. Consequently, when $A^*$ selects a node from the Priority Queue to expand, the shortest path to that node has already been discovered ($g(n) = d^*(start, n)$). No closed node ever needs to be reopened.

### 2.3 Priority Queue Data Structure (Binary MinHeap)
The simulator implements a generic `PriorityQueue<T>` with a 0-indexed contiguous array representing a complete binary tree:
- **Child indexing:** Left child at $2i + 1$, Right child at $2i + 2$.
- **Parent indexing:** $\lfloor (i - 1) / 2 \rfloor$.
- **`enqueue(element, priority)`:** Appends element to array end and invokes `bubbleUp()`. Worst-case comparisons: $\lceil \log_2 N \rceil$. Time complexity: $O(\log N)$.
- **`dequeue()`:** Swaps root with leaf, pops leaf, and invokes `sinkDown()`. Worst-case comparisons: $2 \lceil \log_2 N \rceil$. Time complexity: $O(\log N)$.
- **`isEmpty()` and `size()`:** $O(1)$.

### 2.4 Asymptotic Complexity of 2D $A^*$
- **Time Complexity:**
  Each vertex is enqueued at most once. For each vertex $u$, at most 4 incident edges are examined. Each edge evaluation takes $O(1)$ hash map operations (`visited`, `gScore`) and at most one heap insertion of $O(\log |V|)$.
  $$T_{A^*} = O(|V| \log |V| + |E| \log |V|) = O(|V| \log |V|)$$
  For our $20 \times 14$ grid ($|V| \le 280$):
  $$T_{worst} \approx 280 \times \log_2(280) \approx 280 \times 8.13 \approx 2,276 \text{ operations}$$
  In real execution, planning time is $\le 0.38 \text{ ms}$ and expanded nodes average $25 \pm 4$.

- **Space Complexity:**
  - `openSet` (Binary MinHeap): At most $|V|$ elements $\implies O(|V|)$.
  - `gScore` and `cameFrom` maps: At most $|V|$ entries $\implies O(|V|)$.
  - Total Memory: $O(|V|)$.

## 3. Space-Time Cooperative $A^*$ ($CA^*$) Complexity

### 3.1 3D Space-Time State Formulation
In multi-agent environments, spatial clearance alone is insufficient to prevent collisions. Cooperative $A^*$ elevates the configuration space into a time-indexed graph:
$$S = (x, y, t)$$
Where:
- $(x, y) \in V$ is the 2D spatial coordinate.
- $t \in [0, T_{horizon}]$ is the discrete simulation clock tick ($t \in \mathbb{N}_0$).
- $T_{horizon}$ is the maximum planning horizon (default: $T_{horizon} = 80$ steps).

### 3.2 Action Space and Edge Transitions
From state $u = (x, y, t)$, an AGV has 5 candidate actions to reach a state at timestep $t+1$:
1. **Move North:** $(x, y-1, t+1)$ with cost $1.0$
2. **Move South:** $(x, y+1, t+1)$ with cost $1.0$
3. **Move East:** $(x+1, y, t+1)$ with cost $1.0$
4. **Move West:** $(x-1, y, t+1)$ with cost $1.0$
5. **Wait / Hold:** $(x, y, t+1)$ with cost $1.002$ (includes a $+0.002$ tie-break penalty to discourage idle waiting when unobstructed forward movement is possible).

Branching factor:
$$b \le 5$$

### 3.3 Space-Time Graph Size
The space-time graph $G_{ST} = (V_{ST}, E_{ST})$ has:
$$|V_{ST}| = |V| \times T_{horizon} = 280 \times 80 = 22,400 \text{ states}$$
$$|E_{ST}| \le 5 \times |V_{ST}| \le 112,000 \text{ directed edges}$$

### 3.4 Multi-Agent Prioritized Planning Complexity
For a fleet of $K$ robots, paths are planned sequentially in decreasing order of effective priority:
$$P_{eff}(R_i) = P_{base}(R_i) + \text{age}(R_i)$$

For each robot $k \in \{1, 2, \dots, K\}$:
1. Robot $k$ searches for a path in $G_{ST}$ that does not collide with reservations established by robots $1, \dots, k-1$.
2. Upon finding an optimal collision-free path, robot $k$ records its vertex and edge occupancies into the global `ReservationTable`.

#### Theoretical Worst-Case Time Complexity for $K$ Robots:
$$T_{fleet}(K) = \sum_{k=1}^K O(|V_{ST}| \log |V_{ST}|) = O(K \cdot |V| \cdot T_{horizon} \log(|V| \cdot T_{horizon}))$$
Substituting $|V| = 280$, $T_{horizon} = 80$:
$$|V_{ST}| \log_2 |V_{ST}| \approx 22,400 \times \log_2(22,400) \approx 22,400 \times 14.45 \approx 323,680 \text{ ops per robot}$$
For $K = 10$ robots:
$$T_{fleet}(10) \approx 3.24 \times 10^6 \text{ operations (theoretical upper bound)}$$

In practice, heuristic pruning dramatically restricts search depth:
- Empirical 1 AGV: $0.16 \text{ ms}$ (25 expanded nodes).
- Empirical 10 AGVs: $258.42 \text{ ms}$ (39,326 expanded nodes).

## 4. Reservation Table Data Structure & Conflict Detection

The `ReservationTable` prevents spatial and kinematic conflicts through hash maps.

```
┌─────────────────────────────────────────────────────────────┐
│                      RESERVATION TABLE                      │
├──────────────────────────────┬──────────────────────────────┤
│ Vertex Map: (x, y)@t         │ Key: string -> robotId       │
│ Edge Map:   (u)->(v)@t       │ Key: string -> robotId       │
│ Goal Map:   (x, y)           │ Key: string -> arrivalTime   │
└──────────────────────────────┴──────────────────────────────┘
```

### 4.1 Vertex Conflict Avoidance
- **Definition:** Two robots $R_i, R_j$ cannot occupy cell $(x, y)$ at the same timestep $t$.
- **Lookup Key:** `"${x},${y}@${t}"`
- **Insertion:** `reserveVertex(x, y, t, robotId)` $\implies O(1)$ hash table insert.
- **Query:** `isVertexReserved(x, y, t)` $\implies O(1)$ hash lookup.

### 4.2 Edge-Swap Conflict Avoidance
- **Definition:** Two robots $R_i, R_j$ cannot traverse the same physical edge in opposite directions between $t$ and $t+1$:
  $$R_i: u \rightarrow v \quad \text{at } t$$
  $$R_j: v \rightarrow u \quad \text{at } t$$
- **Mechanism:** Before robot $R$ transitions from $u = (x_1, y_1)$ to $v = (x_2, y_2)$ at time $t$:
  1. The algorithm checks if `(v)->(u)@t` is reserved by querying the directional key `"${x2},${y2}->${x1},${y1}@${t}"`.
  2. If found, the transition is rejected as a kinematic edge-swap conflict.
  3. If free, `reserveEdge(x1, y1, x2, y2, t, robotId)` is recorded.
- **Complexity:** $O(1)$ query, $O(1)$ insertion.

### 4.3 Permanent Goal Reservation
- **Definition:** When robot $R_i$ reaches its destination at timestep $t_{arrival}$, it parks at $(x_g, y_g)$. It must not be collided with by trailing robots at any timestep $t \ge t_{arrival}$.
- **Mechanism:** A goal reservation table stores $(x_g, y_g) \mapsto t_{arrival}$. A prospective transition to $(x_g, y_g)$ at timestep $t$ is valid if and only if $t < t_{arrival}$.
- **Complexity:** $O(1)$ query, $O(1)$ insertion.

### 4.4 Reservation Invalidation & Cleaning
When an AGV completes a mission, is reprioritized, or encounters a dynamic obstacle:
- `clearRobotReservations(robotId)` iterates over the robot's active reservation keys and deletes them from vertex, edge, and goal maps.
- **Time Complexity:** $O(L)$, where $L$ is the path length ($L \le T_{horizon}$).
- **Space Complexity:** $O(K \cdot L)$ entries across all active robots. For 10 robots with average path length 15: $\approx 150$ entries (negligible memory footprint $< 50 \text{ KB}$).

## 5. Collision Manager & Multi-Vehicle Safety Layer

The `CollisionManager` (`src/algorithms/collisionManager.ts`) provides a deterministic runtime safety barrier between planned paths and execution.

### 5.1 Verification Logic Flow
```
Step Candidate Moves for All AGVs
               │
               ▼
   [Filter Out-of-Bounds & Static Obstacles]
               │
               ▼
   [Lock Cells of Stationary AGVs (from === to)]
               │
               ▼
   [Detect Simultaneous Target Conflicts (Move vs Move)]
               │
       ┌───────┴───────┐
   (Conflict)      (No Conflict)
       │               │
       ▼               ▼
[Yield Lower Priority] [Approve Step]
       │
       ▼
[Cascading Chain Yield Loop]
 (Ensure Trailing Robots Yield)
```

### 5.2 Stationary Occupant Invariance (Defect DEF-01 Resolution)
In industrial material handling, a parked or stationary loading AGV has absolute right-of-way over any approaching AGV, regardless of the approaching vehicle's mission priority:
$$\text{If } \text{pos}_{R_j}(t) = \text{target}_{R_j}(t+1) \implies \text{cell } \text{pos}_{R_j} \text{ is unconditionally locked}$$
Any moving robot $R_i$ attempting to step into $\text{pos}_{R_j}$ is denied and forced to hold at its current coordinate.

### 5.3 Cascading Chain Yield Resolution (Defect DEF-02 Resolution)
When robot $R_k$ yields and is forced to hold at $\text{from}_{R_k}$, its origin cell $\text{from}_{R_k}$ remains occupied at $t+1$. Any trailing robot $R_m$ whose intended target was $\text{from}_{R_k}$ must now also be forced to yield.

The algorithm executes an iterative fixed-point loop:
```typescript
let changed = true;
while (changed) {
  changed = false;
  for (const robot of movingRobots) {
    if (approvedMoves.has(robot.nextCell) && isOccupiedByYieldedRobot(robot.nextCell)) {
      forceYield(robot);
      changed = true;
    }
  }
}
```
- **Loop Termination:** At most $K$ iterations (in the worst case of a linear platoon of $K$ robots yielding in cascade).
- **Time Complexity:** $O(K^2)$ worst case, $O(K)$ typical. For $K = 10$, $\le 100$ operations ($< 0.02 \text{ ms}$).

## 6. Deadlock Detection & Starvation Recovery

### 6.1 Wait-For Graph (WFG) Formulation
A dynamic directed dependency graph $G_{WF} = (V_{WF}, E_{WF})$ is constructed at each simulation tick:
- **Vertices $V_{WF}$:** The set of active AGVs $\{R_1, R_2, \dots, R_K\}$.
- **Directed Edge $(R_i \rightarrow R_j) \in E_{WF}$:** AGV $R_i$ is waiting to enter the cell currently occupied by AGV $R_j$.

Because an AGV can only attempt to traverse into at most one cell at any single tick:
$$\text{Out-degree}(R_i) \le 1, \quad \forall R_i \in V_{WF}$$
$$\therefore |E_{WF}| \le |V_{WF}| \le K$$

### 6.2 Cycle Detection Algorithm (Depth-First Search)
The system executes a cycle-finding DFS with three-color node marking (White = unvisited, Gray = active in current recursion stack, Black = fully explored):
- If an edge $(u \rightarrow v)$ is traversed and $v$ is Gray, a directed cycle exists.
- The cycle represents a **circular wait deadlock** (Coffman Condition 4).
- **Time Complexity:**
  $$T_{WFG} = O(|V_{WF}| + |E_{WF}|) = O(K + K) = O(K)$$
  Cycle detection runs in linear time relative to fleet size. For $K = 10$, DFS completes in $< 0.01 \text{ ms}$.

### 6.3 Differentiation Between Temporary Waiting and True Deadlock
A single AGV waiting behind another moving vehicle does not constitute a deadlock:
1. If $R_1 \rightarrow R_2$ and $R_2$ is moving forward ($R_2 \rightarrow \emptyset$), no cycle exists.
2. Even if $R_2$ is temporarily stopped, a deadlock alert is only declared if the wait counter exceeds the starvation threshold:
   $$\text{waitTicks}(R_i) \ge \tau_{deadlock} = 3 \text{ ticks}$$
This prevents spurious replanning disruptions during routine traffic flow.

### 6.4 Priority Aging & Cycle Inversion
When a cycle $C = (R_1 \rightarrow R_2 \rightarrow \dots \rightarrow R_m \rightarrow R_1)$ is verified:
1. The lowest-priority robot in the cycle $R_{min} = \arg\min_{R \in C} P_{eff}(R)$ is identified.
2. Its priority age is boosted:
   $$\text{age}(R_{min}) \leftarrow \text{age}(R_{min}) + 15$$
3. Reservations for the entire cycle are invalidated in the `ReservationTable`.
4. Paths are replanned in the updated priority sequence.
5. With $R_{min}$ now possessing higher effective priority, it reserves its egress route first, forcing the opposing robot to wait at a turnout siding and permanently dissolving the cyclic deadlock.

## 7. Dynamic Sensing & Real-Time Replanning

When an unforeseen obstacle appears at coordinate $(x_{obs}, y_{obs})$:
1. **Affected AGV Filtering:**
   Only robots whose planned future trajectories intersect $(x_{obs}, y_{obs})$ are flagged:
   $$\text{Affected}(R_i) \iff \exists t \ge t_{curr}: \text{path}_{R_i}(t) = (x_{obs}, y_{obs})$$
2. **Reservation Invalidation:**
   Future reservations for affected robots from $t_{curr}$ onwards are revoked.
3. **Local Space-Time Detour:**
   Cooperative $A^*$ replans a detour from the robot's current coordinate $(x_{curr}, y_{curr}, t_{curr})$ to the existing target destination.
4. **Fleet Invariance:**
   Robots operating in non-intersecting aisles experience zero replanning latency and maintain their planned trajectories without interruption.

## 9. Architectural Scalability for Large-Scale Fleets (100+ AGVs)

While Cooperative $A^*$ with Prioritized Planning is optimal and highly responsive for localized warehouse zones (up to 15-20 AGVs per zone), scaling to facility-wide fleets (100+ AGVs across $200 \times 200$ fulfillment centers) warrants three architectural extensions:

### 9.1 Windowed Hierarchical Cooperative $A^*$ (WHCA*)
- Instead of planning across the entire mission horizon ($T_{horizon} = 80$), paths are planned within a rolling time window $w \in [t, t + 16]$.
- Reduces space-time graph size from $W \times H \times 80$ to $W \times H \times 16$, cutting node expansions by over $75\%$.
- Robots periodically replan as the window slides forward.

### 9.2 Conflict-Based Search (CBS / ECBS)
- Prioritized Planning is incomplete and can fail if a high-priority robot irrevocably blocks a lower-priority robot.
- Conflict-Based Search operates on a two-level search: a high-level search over a Conflict Tree and low-level single-agent $A^*$ searches.
- Guaranteed to find the Pareto-optimal makespan solution for tight multi-robot coordination.

### 9.3 Directional Aisles & Warehouse Topology Engineering
- By assigning alternating one-way directions to warehouse rack aisles (e.g. Aisle 1 Northbound, Aisle 2 Southbound), opposing head-on edge swaps are eliminated by environmental design.
- Reduces MAPF complexity closer to single-agent $A^*$ with queueing.
